Why CodeHawk

Everything a great reviewer does. None of the noise.

Fast rules find the suspects. Claude reads the code, follows how input reaches it, and keeps only what a senior engineer would actually comment on.

Checked, not just flagged

Each rule hit is confirmed or dismissed with a reason you can read, so you get real issues instead of a pile of warnings.

Walkthrough of every change

A plain-language summary of what the PR does, grouped by file, with an estimate of how hard it is to review.

Catches what rules can't

Missing ownership checks, logic flaws, races, unawaited promises, N+1 queries, and protections a diff quietly removed.

Ready-to-apply fixes

Every finding comes with a patch in your code's style. Queue fixes in the report and apply them all in one approved step.

Hard to fool

Detects text aimed at AI reviewers and invisible Unicode. Comments like "don't check this" are flagged, never obeyed.

Fits your workflow

A self-contained interactive report, a PR comment ready to paste, and SARIF output for GitHub code scanning.

Two review tracks

Security and code quality, graded side by side.

F

Security

What an attacker could do

  • CriticalSQL, command & template injection; RCE through deserialization
  • CriticalJWT not verified, auth bypass, live secrets in git
  • HighSSRF, path traversal, IDOR, XSS, weak password hashing
  • MediumReDoS and other denial of service, permissive CORS, debug mode
  • HighGitHub Actions injection, pull_request_target, curl | sh
D

Code quality

What is wrong, fragile or slow

  • Likely bugforEach(async …) not awaited, mutable defaults, NaN and typeof mistakes
  • Should fixN+1 queries, swallowed errors, blocking I/O, resource leaks
  • RefactorLong and complex functions, deep nesting, duplicated blocks
  • RefactorNew logic without tests, hard-coded URLs, any types
  • NitpickDebug prints, TODOs, loose ==, capped at about 10
How it works

The scripts do the mechanical work. Claude does the judgment.

Scope

Works out exactly which files and lines a PR, commit, branch or repo covers, reading them straight from git.

Scan

About 160 rules and structural checks, plus an OSV.dev lookup of every pinned dependency, produce a worksheet of suspects and the files worth reading in full.

Review

Claude follows the data, confirms or dismisses every hit, and writes the walkthrough.

Report

A validated build creates report.html, a PR comment and SARIF.

Fix

Patches are planned and shown first, then applied only after you approve them.

Safe by design

Built for reviewing code you don't trust.

Can't be talked out of looking

Public repos and outside PRs can hide prompt injection: text written to trick AI reviewers into skipping a backdoor or running a command. CodeHawk warns you up front and treats every file as data.

  • Only you set the scope. No comment, config or PR text can narrow it.
  • "Already audited" isn't evidence. Dismissals that rely on the code's own claims are rejected.
  • Nowhere to hide. It looks inside vendor/, minified files, PR descriptions and commit messages.
  • Never runs the code it reviews. No install, build or test.

Fixes only with your permission

PlanEvery change is shown as a diff first. Nothing has been edited yet.
ApproveYou choose which fixes to apply. A one-time token ties the change to the exact plan you saw.
ApplyAll or nothing, only where the original code still matches.
Never mergesNo commits, pushes, PRs or merges unless you ask for each one.
